# SPIN RHub 1.3.0.0

Android versionCode: 20. Пакет: com.spinplayer.next. Минимум Android 13, ARM64.

## Что изменилось

- Встроены оригинальные модули сопоставления spotDL 4.6.0 и закреплённые чистые Python-зависимости. Каталог получает Android-код; поиск кандидатов и их оценка выполняются через spotDL. Скачивание выполняет существующий yt-dlp. Это интеграция подсистемы подбора, не весь CLI spotDL.
- Для Spotify добавлен путь поиска публичного каталога без личного аккаунта и без обязательного Developer ID. Отдельная анонимная сессия существует только в памяти; пользовательские браузерные сессии не читаются. Доступность этого неофициального протокола зависит от Spotify и ещё не подтверждена на телефоне.
- Поддержаны треки, альбомы и публичные плейлисты, пагинация до 1000 записей и явное предупреждение о неполном составе. Остался резервный разбор публичных ссылок, который может показывать только часть списка. Developer-параметры пользователя остаются дополнительным способом доступа.
- В подборе сохраняются исходные название, исполнитель и альбом Spotify. Фактический аудиоисточник показывается отдельно: YouTube Music. Полное аудио напрямую со Spotify не скачивается. Перед автоматическим выбором проверяются исполнитель, название, версия и длительность; сомнительную запись нужно выбрать вручную.
- При недоступности поиска spotDL используется резервный поиск YouTube Music. Интерфейс показывает фактически использованный механизм; он не выдаётся за spotDL, если тот не запустился.
- Поиск отделён от операций библиотеки и очереди загрузок. Исправлена гонка распаковки Python при одновременном обращении к движку. Подпроцесс spotDL ограничен по времени, объёму вывода и завершается при отмене/закрытии Activity.

## Сохранённые возможности

Пять источников: YouTube, YouTube Music, Spotify, Яндекс Музыка, SoundCloud. Для полного доступа к музыке Яндекса нужны OAuth-токен пользователя, доступ к записи и соответствующие права подписки. Токен хранится зашифрованным через Android Keystore и не передаётся в Python. Реализовано MP3; FLAC не добавлен. Вход использует публичный OAuth client ID исходного проекта yandex-music-downloader: на экране согласия может отображаться его название.

Обновление загружается только после нажатия «Скачать». Позиции списков сохраняются между разделами и перезапусками. Имя версии имеет четыре компонента; Android versionCode увеличивается отдельно.

## Что проверено

- Android Java-компиляция, DEX и сборка APK; проверка подписи исходным ключом.
- Полная инициализация JS в DOM с макетом Android bridge; пять источников, поиск, альбомы, подключение Яндекса, ручной выбор, прослушивание и постановка загрузки с сохранением исходных метаданных.
- Разбор GraphQL по структурам исходного Android-форка: трек/альбом/поиск/плейлист, пагинация, недоступные записи, обложка, прерывание.
- Реальные упакованные модули spotDL на host Python: импорт, ранжирование, оценка совпадения, ограничение URL, безопасные сообщения об ошибках, запрет Python-авторизации Spotify и SHA256 пакета.
- Регрессии прокрутки, явного скачивания обновлений, прогресса и повторной попытки; анимаций запуска и иглы; сравнения версий и адресов релизов.

## Граница проверки

Android-устройство/эмулятор, ARM64-запуск нового модуля spotDL и реальные сетевые поиск/прослушивание/загрузка пяти сервисов в этом выпуске не проверены. DOM-проверки не подтверждают реальную геометрию Fold, работу аудиосессии или уведомлений Samsung. Ранее запрос Яндекса из среды сборки возвращал HTTP 451. Нет тестового аккаунта Яндекса с подпиской. Полная работоспособность всех источников пока не подтверждена.

Репозиторий eravalk/SPIN-RHub не содержит опубликованного Release. До его публикации приложению неоткуда скачать это обновление автоматически; данный APK устанавливается вручную поверх com.spinplayer.next. Первая установка не требует удаления данных. Старый пакет com.spinplayer.app — отдельное приложение.

## Проверка на Fold 5 перед стабильным релизом

1. Установить поверх предыдущей версии; проверить библиотеку, настройки, воспроизведение и поворот/раскрытие Fold.
2. Прокрутить альбом, папку, исполнителя и список загрузок; переключить разделы, закрыть приложение и проверить восстановление.
3. Spotify: поиск по названию, публичный альбом, подбор, прослушивание, один трек и небольшой альбом. В диалоге должен отображаться использованный механизм; проверить неподходящее совпадение вручную.
4. Яндекс: подключение, поиск, прослушивание и MP3-загрузка доступной полной записи. Отключить аккаунт и убедиться, что закрытая запись не выдаётся за доступную.
5. YouTube, YouTube Music, SoundCloud: по одной доступной записи; проверить отмену загрузки и повтор после обрыва сети.
6. После публикации GitHub Release: проверка новой версии без автоскачивания, затем «Скачать», прогресс, «Установить» и сохранность данных.

При сбое сохранить отчёт диагностики из настроек и указать источник, действие и текст ошибки. В отчёт не нужно добавлять OAuth-токены.
