# SPIN Player 0.3.5 alpha — текст, импорт и движение иглы

Исправления:
- Источники текстов опрашиваются независимо, общий предел ожидания 25 секунд. Сохраняются ответы успевших сервисов; при уверенном синхронизированном совпадении автоматический поиск завершается раньше. Повторный запрос отменяет прежний, устаревший ответ не применяется.
- Выбор текста и импорт вынесены из общей очереди операций приложения. Результат сохранения передаётся прямо интерфейсу, без повторного чтения мостом.
- Импорт TXT/LRC до 1 МБ: UTF-8, UTF-16 с BOM, Windows-1251. Пустые и бинарные файлы отклоняются. TXT не помечается синхронизированным.
- Вставка/редактирование текста: кнопка на пустом экране и в параметрах текста; сохранение для выбранной песни и офлайна, подтверждение либо ошибка. Максимум 250 000 символов. Файлы не публикуются.
- Неуверенные результаты по-прежнему требуют выбора. Кнопка теперь явно показывает количество найденных вариантов. LRCLIB ищет по одному названию также при наличии неточных совпадений.
- Перетаскивание иглы: локальный предпросмотр через requestAnimationFrame, отключение CSS transition на время касания, одна команда seek при отпускании. Старые события позиции не отбрасывают иглу назад во время жеста. Отмена жеста возвращает начальное положение.
- Канавки, блик, тень и толщина края пластинки поверх выбранной расцветки. Скрытие иглы в режиме фонового винила с текстом оставлено прежним — пользователь уточнил, что проблема именно в задержке движения.

Проверка реальных сервисов из среды сборки: lyrics.ovh HTTP 200 с непустым текстом; LRCLIB HTTP 503; KuGou и QQ через Better Lyrics HTTP 401. Это не подтверждает доступность на телефоне пользователя. Отказы внешних сервисов не устранены кодом; их статус показывается отдельно. Документация Better Lyrics ранее заявляла доступность KuGou/QQ без ключа, но реальный ответ требует доступа.

Проверки: JVM LyricsProviderTest, LyricsSourcesTest, LyricsTextTest, LyricsSearchTest; браузерный ui-check.cjs с моками Android (включая сохранение/ошибку текста, импорт, отсутствие потока seek, защиту жеста от старых событий). Компиляция Android и проверка подписи. Физическое устройство Android и его ContentResolver здесь недоступны, плавность на Fold требует проверки на телефоне.

# SPIN Player 0.3.4 alpha — несколько источников текста

Поверх 0.3.3: выбор «Все источники», LRCLIB, lyrics.ovh, KuGou через Better Lyrics, QQ через Better Lyrics. Выбор сохраняется и применяется к автоматическому и ручному поиску, включая изменённый запрос.

Ручной поиск опрашивает все выбранные источники даже после точного совпадения. Автоматический поиск сохраняет подтверждённое совпадение LRCLIB; при отсутствии уверенного синхронизированного результата запрашивает дополнительные источники. Новые варианты требуют ручного подтверждения, поскольку API Better Lyrics не возвращает проверяемую длительность/полные метаданные найденной записи. Теги LRC/QRC отображаются, если присутствуют. Сохранённый или импортированный текст автоматически не заменяется.

QQ QRC переводится в enhanced LRC с исходными таймингами строк/слов и смещением. Обычный текст не получает выдуманных таймингов. У каждого опрошенного источника отдельный статус: найдено, нет текста, ошибка HTTP, сеть или лимит запросов. Retry-After соблюдается по хосту: KuGou и QQ делят один посредник и его ограничения. После ошибки поиск продолжается в независимых источниках. LRCLIB ограничен девятью вариантами, чтобы оставить место остальным.

Путь: Текст → Параметры текста → Источник поиска → Обновить / другой текст. В списке результатов можно поменять источник и повторить поиск.

Новые источники экспериментальные: в среде сборки оба запроса Better Lyrics получили HTTP 403; реальная выдача и доступность на телефоне не подтверждены. Наличие песни в каталоге не гарантируется. Это четыре источника, но только три независимых сетевых сервиса. Musixmatch/Genius не добавлены под видом работающих API.

Документация интеграции:
- https://lyrics-api-docs.boidu.dev/reference/get-lyrics
- https://lyrics-api-docs.boidu.dev/docs/qrc-format
- https://lrclib.net/docs

Проверки: LyricsProviderTest, LyricsSourcesTest (локальные оригинальные фикстуры; все источники, отдельный выбор, переход после ошибки, QRC, неверный формат, статусы); ui-check.cjs с моками Android; компиляция Android и подпись APK. Реального Android-устройства здесь нет.

Для JVM тестов требуется nanojson.jar и jsoup.jar в classpath. APK подписывается прежним локальным ключом; приватный ключ в исходники не включён.

# Обновление 0.3.3 alpha · обложки, редактор, диагностика текстов

Установить поверх 0.3.2 без удаления приложения.

- ArtworkUrl/ArtworkCache: разрешены HTTPS-хосты googleusercontent.com (обложки YouTube Music), ggpht.com, ytimg.com, sndcdn.com с проверкой границ домена. Поддерживаются ссылки //host/path. Реальные PNG/WebP/JPEG декодируются, уменьшаются до разумного размера и сохраняются как JPEG; пустые/HTML-ответы не выдаются за изображение. При отсутствии картинки YouTube используется миниатюра по video ID. При ошибке показана заглушка, причина записана в отчёт. Исправление касается превью обложек; аудиопрослушивание результатов поиска не добавлялось.
- Нативный редактор: выбор обложки через Android ACTION_OPEN_DOCUMENT, обработка через ContentResolver/BitmapFactory, предпросмотр выбранного изображения. Браузерный input file/blob для нативных треков не используется. Название/исполнитель/альбом/подготовленная обложка сохраняются одной командой. Библиотека записывается с commit, успех передаётся интерфейсу после подтверждения; ошибка видна и не закрывает редактор. Обновляются группировка, текущая MediaSession и виджеты. Отмена выбора/редактора не применяет обложку. Оригинальные аудиофайлы остаются прежними. Выбрано adjustResize, системные отступы отделены от клавиатуры.
- Поиск текста выполняется в отдельной рабочей очереди, независимо от поиска альбомов/чтения тегов. Пользовательский запрос названия/исполнителя запоминается для песни и используется при повторном поиске. Изменение тегов сбрасывает этот запрос. Лимит LRCLIB останавливает запросы к нему, но не исключает обращение к резервному lyrics.ovh. Сохранённые тексты/сдвиг времени сохраняются.
- Отчёт TXT доступен в настройках и параметрах текста. Записываются этапы, хост, HTTP-код, длительность запроса, количество кандидатов, тип ошибки, подтверждение редактирования и категория ошибки WebView. Не записываются поисковая строка, текст песни, cookies, ключи или подписанные медиа-URL. Отправки отчётов по сети нет: пользователь сохраняет и прикрепляет TXT самостоятельно.

Проверено: Java/D8/подпись, изолированные тесты допустимых и запрещённых хостов/миниатюры, тесты алгоритма LyricsProvider, Chromium UI с native bridge-заглушкой (обложка Googleusercontent, нативный выбор обложки, ожидание сохранения, обработка ошибки, обновление сведений, ручной поиск и отчёт). Настоящий ContentResolver/SharedPreferences/Android клавиатура на устройстве в этой среде не запускались.

Реальные сетевые пробы: LRCLIB вернул 502, www.lrclib.net — 525, lyrics.ovh вернул JSON с текстом и HTTP 200. Успешное получение текста из LRCLIB на Fold пока не подтверждено. Для диагностики на телефоне повторить поиск и сохранить TXT. Полный текст песен в тестовые артефакты не включался. Прежние возможности и ограничения ниже.

# Обновление 0.3.2 alpha · поиск альтернативного названия

Установить поверх 0.3.1. Добавлен отдельный поисковый запрос, который не меняет теги файла: «Текст → Параметры текста → Изменить поисковый запрос». Поля названия и исполнителя позволяют указать английское название/транслитерацию/основного исполнителя. Результат подтверждается пользователем. Это общий механизм, в приложение не вшиты тексты или алиасы конкретной песни.

При успешном ответе LRCLIB и отсутствии результатов добавлен поиск только по названию; кандидаты по-прежнему проверяются на исполнителя, длительность и версию, сомнительные не выбираются автоматически. При HTTP 5xx/сетевой ошибке дополнительные запросы к LRCLIB прекращаются, вместо повторения одной неудачи используется резерв. UI различает отсутствие совпадений, HTTP-код, DNS, таймаут и лимит источника. Кнопка возврата к текущей строке скрыта без синхронизированного текста.

Проверки: компиляция Java/D8, подпись, изолированные тесты поиска только по названию/составного исполнителя/HTTP 502 и предыдущих сценариев, Chromium UI с заглушкой bridge — поля пользовательского запроса и скрытая кнопка без таймингов. Реальные запросы для японского названия и составного исполнителя в этой среде вернули HTTP 502. Успешное получение текста этой песни из LRCLIB не подтверждено; на Android 0.3.2 ещё не запускалась.

# SPIN Player 0.3.0 alpha · Galaxy Z Fold 5 / ARM64

Установить SPIN-Player-0.3.0-alpha.apk поверх 0.2.0, без удаления приложения. Сохранены package com.spinplayer.app и прежний сертификат подписи. Минимальная версия Android 13 (API 33), target 35. Этот APK содержит ARM64 Python, FFmpeg и QuickJS, поэтому рассчитан на Fold 5 и другие ARM64-устройства. Виджеты после обновления при необходимости удалить с рабочего стола и добавить заново.

## Музыка на устройстве
Настройки → «Музыкальные папки» → «Выбрать папку». Системный выбор Android выдаёт сохраняемый доступ к дереву документов, включая подпапки. Поддерживаются несколько деревьев. «Обновить» находит новые файлы и убирает исчезнувшие из библиотеки при успешно завершённом обходе. Частичная ошибка обхода не удаляет старые записи. Отключение папки удаляет только её принадлежность в библиотеке, не файлы. При перекрывающихся папках сохраняются остальные принадлежности. Документные URI и MediaStore основной памяти сопоставляются по идентификаторам/относительному пути, чтобы не добавлять один файл повторно. Копии файлов у разных провайдеров не считаются одним файлом по содержимому. Сканирование выполняется вручную, не является наблюдателем файловой системы. Во время большого сканирования держать приложение открытым. Сохраняются также прежний импорт отдельных файлов и редактор названий/обложек.

## Онлайн
Поиск → «В интернете». YouTube Music ищет раздел «Песни», YouTube — видео; отдельно есть поиск альбомов YouTube Music и открытие HTTPS-ссылки на подборку YouTube/SoundCloud. Список альбома ограничен 100 записями; перед загрузкой проверь полноту. Все песни отмечены по умолчанию, можно снять отметки. Качество альбома: лучшее доступное, AAC/M4A или Opus при наличии. Для отдельной песни yt-dlp получает фактические аудиоформаты, отображает битрейт и размер, если они доступны. Невозможный формат завершится ошибкой, искусственного повышения качества нет.

Карточка показывает обложку, исполнителя, длительность, источник и признаки live/remix/cover/slowed; верификация канала и название не являются гарантией оригинального мастера. Spotify убран из интерфейса. SoundCloud явно отмечен экспериментальным: новый успешный тест реального сервиса на Android не получен.

Очередь yt-dlp последовательная, отдельная foreground dataSync-служба с уведомлением и ограниченной wakelock. Скачивание продолжается при свёрнутом приложении в пределах ограничений Android. Во время работы соблюдается «Только Wi-Fi»; после подключения нажать «Продолжить очередь». Прерывание процесса не выдаётся за успех: прерванные активные задачи помечаются ошибкой, их можно повторить. Полного восстановления текущего скачивания после убийства процесса нет. Неполные файлы не публикуются. Ошибка одной песни не останавливает остальные. Отмена активного задания проверяется watchdog движка. До сохранения проверяются наличие аудиодорожки и декодирование первых примерно трёх секунд. Публикация через MediaStore в Music/SPIN/Исполнитель/Альбом. Добавление в библиотеку автоматическое; метаданные хранятся в MediaStore/SPIN, обложки — в приватном кэше SPIN. Обложки не встраиваются в аудиофайл. Старые незавершённые задания DownloadManager переводятся в повторяемую ошибку, чтобы старый и новый движки не скачивали одну запись одновременно.

## Текст и визуальная часть
Кнопка «Текст» включает/выключает постоянный режим. Выбор хранится при перезапуске. При смене песни открытый текст обновляется. Найденный LRCLIB-текст и импортированный LRC сохраняются на устройстве. При отсутствии кэша и включённом режиме выполняется автоматический поиск один раз на трек за сеанс; «Параметры текста» позволяет повторить поиск и импортировать LRC, есть сдвиг таймингов. Для подсветки слов нужны тайминги слов; они не синтезируются из обычного текста.

На внешнем экране текст показывается поверх приглушённого вращающегося диска. На внутреннем (от 600 CSS px при автоматической компоновке) панель текста заменяет область списка; крестик возвращает список. Навигация в настройки/поиск доступна независимо от открытого текста. Автопрокрутка следует таймингам; после ручного скролла есть «К текущей строке». Настраиваются размер, жирность, затемнение и перемотка по нажатию на строку (выключена по умолчанию). Экран гаснет по системному таймеру, FLAG_KEEP_SCREEN_ON не используется.

Винил плавно разгоняется/останавливается и сохраняет угол между перерисовками; вращается диск, не игла. Волнообразный ползунок внутри приложения, на паузе ровный, с широкой областью захвата и предпросмотром времени при перемотке. Можно выключить анимации. Персональные узоры/цвета винила сохраняются отдельно для песен (25 оформлений). Акцент из обложки либо ручной, плавные состояния элементов, индикатор играющего трека и длительность альбомов.

Системная MediaSession передаёт название, исполнителя, длительность, текущую позицию, управление и статичную миниатюру винила. Цвет извлекается из обложки. Ползунок, компоновка и окончательный фон уведомления/Now Bar определяются One UI; точное совпадение с концептом не гарантируется. Вращение в уведомлении не реализуется частыми обновлениями картинок. Виджеты сохранены.

SPIN_SDK=<Android SDK с build-tools/35.0.0 и platforms/android-35> SPIN_ECJ_JAR=<ECJ jar> bash build-local.sh
