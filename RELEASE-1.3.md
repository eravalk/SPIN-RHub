# SPIN RHub 1.3 — тестовая интеграция источников

Версия Android: 1.3, versionCode 18, пакет com.spinplayer.next. Обновление поверх 1.2 тем же сертификатом. Требуется Android 13+ / ARM64.

## Что добавлено

- В выборе источника: YouTube, YouTube Music, Spotify, Яндекс Музыка, SoundCloud.
- Яндекс: отдельное подключение аккаунта, поиск песен и альбомов, открытие треков, альбомов и плейлистов по ссылке, предпрослушивание, выбор доступного MP3 и очередь скачивания. Альбомы обрабатываются с учётом дисков, до 500 песен с явным признаком ограничения.
- Загрузчик Яндекса потоково пишет аудио на диск, проверяет размер при наличии, учитывает отмену и Wi-Fi, проверяет декодирование и длительность перед публикацией. Передача OAuth-токена на CDN не выполняется.
- Spotify: публичные полные ссылки open.spotify.com на треки, альбомы и плейлисты открываются через метаданные embed-страницы. Состав публичной подборки может быть неполным, об этом показано предупреждение.
- Поиск Spotify по названию и полная постраничная загрузка списка альбома реализованы через официальный Spotify Web API. Для них нужно подключить каталог собственными Client ID и Client Secret в приложении. Обычный вход пользователя Spotify не заменяет эти параметры.
- Для песни Spotify предлагаются кандидаты YouTube Music: можно послушать, выбрать запись и качество скачивания. Сохраняются исходные сведения Spotify и отдельный адрес реального источника аудио. Прямое аудио Spotify не скачивается.
- При скачивании Spotify-альбома автоматический подбор требует близкого совпадения названия, исполнителя и длительности; live/remix/cover/remaster и другие отличающиеся версии отклоняются. Неуверенная песня получает ошибку, остальные продолжаются. Для неё можно выбрать запись вручную через просмотр альбома.
- Подключения Яндекс/Spotify хранятся в AES-GCM с ключом Android Keystore, не передаются в JavaScript или отчёты. Нативное окно ввода защищено от снимков экрана. Есть отключение сервиса.
- Сохранены постоянные позиции прокрутки и ручное скачивание обновления из 1.2.

## Подключение Яндекса

В «Настройки → Музыкальные сервисы» нажать «Подключить» для Яндекс Музыки, затем «Открыть вход». Вход и пароль вводятся только на странице Яндекса в браузере. После подтверждения скопировать полный адрес с access_token и вставить его в защищённое поле приложения. SPIN извлечёт токен, проверит /account/status и сохранит его на телефоне. Токен или этот адрес не следует присылать в чат.

В этой тестовой интеграции использован публичный OAuth client_id из указанного пользователем проекта yandex-music-downloader. Название приложения на странице согласия определяется этим клиентом. Для отдельного брендированного входа SPIN нужен собственный зарегистрированный OAuth-клиент Яндекса.

Поиск сначала пробуется с доступным подключением, а без него — анонимно; отсутствие входа не скрывается под сообщением «ничего не найдено». Прослушивание и скачивание требуют подключённого аккаунта. Реальная доступность каталога, качества и записи определяется Яндексом. FLAC и расшифровка потоков в 1.3 не реализованы: поддерживается выдаваемый аккаунту MP3. Полученный короткий фрагмент не публикуется как полный трек, если известная длительность не совпала.

## Подключение каталога Spotify

Для публичных ссылок ключи не нужны. Для поиска по названию нажать «Подключить каталог Spotify», открыть Spotify Developer и указать Client ID и Client Secret собственного приложения в нативном окне. Секрет не зашит в APK. Условия получения доступа и ограничения Web API зависят от Spotify. Доступ без настроенного приложения в этой версии не обещается.

Приложение не обращается к неофициальному API с анонимными/пользовательскими токенами, извлечёнными из публичной страницы. Публичная страница используется только для сведений о песне/альбоме; её session-поля не читаются и не используются.

## Проверка и ограничения

- Android-компиляция, D8, упаковка и проверка прежней подписи.
- JVM: проверка адресов поставщиков и CDN, формы метаданных Яндекса/Spotify, разбор embed-данных и правил сопоставления песен, включая отклонение другого исполнителя, длительности и live-версии.
- DOM-тест с имитацией Android: загрузка всех JavaScript приложения, пять источников, поиск песен/альбомов Яндекса, подключение сервиса, Spotify-ссылки, выбор/прослушивание кандидата и сохранение исходных метаданных при загрузке.
- Регрессии постоянной прокрутки, обновлений и анимации иглы.

На реальном Android и с реальными аккаунтами новая интеграция ещё не проверена. В среде подготовки анонимный запрос Яндекса вернул HTTP 451; это не доказывает доступность или недоступность на телефоне пользователя. Получение публичных метаданных Spotify-альбома в среде подготовки прошло успешно, но не является проверкой поиска Web API, полного воспроизведения или скачивания.

Репозиторий GitHub по-прежнему требует публикации релиза с APK, чтобы автоматическая проверка обнаруживала его. Сборка 1.3 не опубликована туда автоматически.
